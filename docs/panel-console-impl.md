## 0. Термины и факты, на которые опираемся (проверено в коде)

- DMX-вселенная = **512 каналов** (одна, `DMX_CHANNELS=512`). Сцены = снепшоты 512.
- Физические кнопки крыла (28 шт): keypad **42–45, 50–53, 57–61, 64–70**,
  нижний ряд/функции **112–119, 126**. Расшифровка (панель `COB_5_v3.0.html` HW_MAP):
  - цифры keypad: 58=1, 59=2, 60=3, 50=4, 51=5, 52=6, 42=7, 43=8, 44=9, 66=0
  - функции keypad: 45=+, 53=Thru, 61=−, 69=At, 68=If, 67=., 64=Store, 57=Clear, 70=Please
  - нижний ряд (над фейдерами 3–8): 112=1, 113=2, 114=3, 115=4, 116=5, 117=6
  - над фейдерами 1–2: 126=Go+, 119=Go−; 118=Pause (= блекаут, уже так)
- **NUM-блок** = цифры keypad (1–9,0). **Нижний ряд** = 112–117 (подписи 1–6).
- **ALT-кнопки на крыле НЕТ** — лучший кандидат: **Please (70)** (сейчас пустая, `channel:null`).
- Приоритет выхода (утв.): **blackout > ALT-программер > флеш (255, без мастеров) > активная NUM-сцена > 0**.
- Диммер-супермастер — умножение. Для приборов БЕЗ диммер-канала (led_par, comb_rgbw) —
  механика яркости: масштабируется RGB(W).
- Выход в линию: `WingSender` (HTP-микс по источникам, bypass по умолчанию ВКЛ, блекаут = нулевой кадр).

## 1. Архитектура: консоль = отдельный движок на сервере

**Принцип:** движок консоли живёт НА СЕРВЕРЕ (единое депо, источник правды).
Крыло и все веб-панели — только ввод + индикация. Панель больше НЕ пишет
`{ch,val}` напрямую и НЕ играет сцены сама — она шлёт консольные события.

```
крыло (фейдеры/кнопки)  ──parse──►  WingInputMapper ──events──►  ConsoleEngine
веб-панель (клики)      ──ws console──►  server ws_handler ────►  ConsoleEngine
                                                                     │
                                               вычисляет frame 512   │
                                                                     ▼
                                        CONSOLE_SOURCE (источник в WingSender,
                                        HTP-микс + bypass + blackout)
                                                                     │
                                              console_state ──ws──►  все панели (LED/слоты/сцены)
```

- Новый модуль **`console_engine.py`** рядом с `server_v4.py`; класс `ConsoleEngine`.
- `server_v4.py` подключает: `_on_wing_event` → и в `broadcast_wing_event` (для вспышек панели),
  и в `console_engine.on_input('wing', kind, id, value)`.
- WS `{type:'console', ...}` → `console_engine.on_input('web', ...)`.
- Движок пишет выход в новый источник `CONSOLE_SOURCE = 'console'` через новый метод
  `WingSender.set_source_frame(CONSOLE_SOURCE, frame)` (замена буфера под `_lock` + ремикс 512).
- `CONSOLE_SOURCE` — НЕ list-источник ⇒ в bypass линия = консоль (+ прочие single-источники),
  в обычном режиме консоль HTP-суммируется с автоматикой Lumina (list-источники) — как сейчас панель.

## 2. Данные движка (ConsoleEngine)

```python
self.mode = 'normal'            # 'normal' | 'alt'
self.alt_page = 1               # страница каналов (по 8) в ALT
self.selected = set()           # выбранные слоты (номера '0'..'9', '11'..'16')
self.masters = {'dimmer': 0, 'strobe': 0}     # 0..255, фейдеры 1-2
self.submasters = [0]*6          # фейдеры 3-8 → сцены 11-16
self.active_num = 0              # активная NUM-сцена (1..10), 0 = нет
self.flash_held = set()          # зажатые флеш-кнопки нижнего ряда (11..16)
self.programmer = {}             # {ch(1-based): val}, только «тронутые» (ALT)
self.store_armed = False         # STORE мигает
self.scenes = load_console_scenes()   # {n: {ch: val}} n=1..16, val>0 (ноль = отсутствует)
# производные:
self._scene_frame = bytearray(512)  # НЕзамастерённый слой (для Store и зеркала)
self._out_frame = bytearray(512)    # после мастеров (пишется в CONSOLE_SOURCE)
```

**Слоты** — отдельный конфиг `console_slots.json` (см. §7), грузится при старте.
Движок по нему строит `channel_roles[512]` и список приборов для мультизаписи.

## 3. Расчёт канала (точная механика)

Роли канала по типу прибора (зеркало `FIXTURE_LAYOUTS`, `web/constants.ts`):

| type | диммер | строб | RGB (механика яркости) |
|---|---|---|---|
| `dimmer` (PAR/wash) | off 0 (Int) | — | — |
| `led_par` (кулисы) | — (RGB) | off 4 | off 0,1,2 |
| `led_par_8ch` (COB) | off 0 (Mast) | off 5 | — |
| `spider` | off 2 (Mast) | off 3 | — |
| `mini_par` | off 0 (Mast) | off 5 | — |
| `comb_rgbw` (расчёска) | — (RGBW) | — | off 2..41 (40 бимовых) |
| `spark`, `laser` | — | — | — |

`channel_roles[ch]` ∈ {`dimmer`, `strobe`, `rgb`, `other`}; неохваченные каналы = `none`.

**Алгоритм (`_compute_frame`, запускается при ЛЮБОМ изменении состояния):**

```
1. СЦЕНЫ (слой) — три уровня, приоритет сверху вниз:
   a) ФЛЕШ (зажатые кнопки 11–16): пока кнопка нажата — ЗАМЕНА всей картинки
      (HTP-max зажатых флешей). Сырые значения, мастера НЕ применяются.
      Кнопка отжата → возвращается состояние из (b)/(c). Флеш перекрывает
      и субамастер своей сцены (флеш = 100% сцены).
   b) СУБМАСТЕРА (фейдеры 3–8): каждый поднятый фейдер = его сцена × уровень.
      Несколько поднятых — НАЛОЖЕНИЕ (HTP-max), поверх активной NUM-сцены.
      Мастера применяются.
   c) БАЗА: активная NUM-сцена (1–10), свитч (одна, повтор = off). Мастера применяются.
   d) Пусто: все нули.

2. _scene_frame[ch] = programmer[ch], если канал тронут, иначе слой сцены (0..255).

3. МАСТЕРА применяются ТОЛЬКО к слою сцен (b/c — флеш и программер их НЕ проходят):
   для каждого ch: role = channel_roles[ch]
     role=='dimmer' или 'rgb' → v = v * dimmer/255
     role=='strobe'            → v = v * strobe/255
     иначе                     → без изменений

4. _out_frame = результат по шагам 1-3. Пишем в CONSOLE_SOURCE.
5. Блекаут НЕ трогает движок — нулевой кадр ставит WingSender поверх (и _line_frame).
```

**Программер = ПРЯМЫЕ физические значения (0–255 = физ. максимум), БЕЗ мастеров.**
Мастера (диммер/строб) в режиме ALT НЕДОСТУПНЫ (фейдеры 1–2 правят каналы прибора),
их позиции заморожены; оператор может сам писать диммер/строб-каналы через ALT.

Хранение сцен — только ненулевые каналы (`{ch: val}`, val>0). При игре отсутствующий канал = 0.

**Store (запись сцены N):** снепшот = `_scene_frame` (НЕзамастерённый, сырые значения:
программер, где тронут, иначе слой сцен — флеш в запись не входит, он мгновенный),
ненулевые каналы → `scenes[N]` → `scenes_store.json` → бродкаст `scene_store`/`console_state` → волна на крыло.

**Priority внутри канала:** блекаут (источник) > программер (шаг 2) > слой сцены (шаг 1) > 0. ✓

## 4. Ввод (крыло и веб — один движок)

`ConsoleEngine.on_input(source, kind, id, value)`:

| Орган | Обычный режим | ALT |
|---|---|---|
| фейдер 1 | dimmer master | канал 1 выбранного прибора |
| фейдер 2 | strobe master | канал 2 |
| фейдеры 3–8 | субамастера сцен 11–16 (наложение) | каналы 3–8 |
| keypad цифра 1–9,0 | сцена 1–10 (свитч, повтор = off) | выбор слота 1–10 (мульти) |
| нижний ряд 112–117 | флеш-сцена 11–16 (вниз/вверх) | выбор слота 11–16 (мульти) |
| Go+ 126 / Go− 119 | no-op | страница каналов вверх/вниз |
| Store 64 | режим записи (armed), повтор = disarm | совместим (запись программера) |
| Clear 57 | стирает программер + disarm Store | то же |
| **Please 70 = ALT** | переключение ALT | — |
| Pause 118 | blackout (уже есть) | blackout |

Мастера 1–2 в ALT НЕДОСТУПНЫ (заморожены) — фейдеры правят «физические» каналы
прибора; вход/выход ALT ничего не сбрасывает и не переключает.
Клавиатура ПК: Numpad0 = блекаут, цифры 1–9 = сцены 1–9 (в обычном режиме).

**Мультизапись (ALT):** `chanfader(f, v)` → для каждого выбранного слота и каждого его
прибора: `idx = (page-1)*8 + (f-1)`; если `idx < channels(прибора)` → `programmer[start+idx] = v`.
Каналы, где прибора нет, не пишутся. Фейдер в ALT показывает `programmer[ch]` (0, если не тронут).

**Выход из ALT** ничего не сбрасывает (программер остаётся в выходе до CLEAR). ✓

**Крыло:** `WingInputMapper` в новом режиме `console_mode=True` НЕ пишет в DMX для
фейдеров/кнопок (только `on_event`); энкодеры продолжают прямой роутинг на 41–44
(стопгап до «color-энкодеров», см. вопросы). Флаг даёт аварийный откат к старому роутингу.

**Веб:** панель шлёт `{type:'console', action, ...}` (см. §6); те же ветки движка.

## 5. Состояние → панели (WS-протокол, новые сообщения)

Server→client:
- `{type:'console_state', payload:{mode, alt_page, selected, masters, submasters,
  active_num, flash_held, store_armed, slots:[{num,name,devices}], scenes:[n...],
  blackout}}` — полный слепок, на коннект и при каждом изменении (троттл 0.2с, как depot_live).
- `{type:'depot_live', payload:{channels:{...ненулевые канала из _out_frame}, faders:[позиции
  фейдеров по режиму: master/sub/chan], encoders:[...]}}` — существующий канал зеркала.
- `{type:'wing_input', ...}` — остаётся для вспышек панели и LED-волн.

Client→server (`{type:'console', action, ...}`):
- `action:'alt', on:0/1` · `action:'slot', num, on:0/1` · `action:'page', dir:1/-1`
- `action:'master', idx:1/2, v` · `action:'sub', idx:3..8, v`
- `action:'chanfader', fader:1..8, v` (только в ALT)
- `action:'num', n:1..10, on:0/1` · `action:'flash', n:11..16, on:0/1`
- `action:'store', on:0/1` · `action:'clear'` · `action:'scene_rec', n`
- `{type:'blackout', set}` — без изменений.

Физические кнопки крыла приходят в движок напрямую (не через WS), но панель их видит
через `console_state` + `wing_input` (вспышки). Кнопки панели (клик) шлют те же `action`.

## 6. Веб-панель COB_5_v3.0.html — что меняется

- **Ввод:** вместо `sendChan({ch,val})` — консольные action'ы.
  - фейдеры master1/2 → `master`, ch1–ch6 → `sub` (норма) / `chanfader` (ALT).
  - keypad-цифры → `num` (норма) / `slot` (ALT); нижний ряд (112–117 пады) → `flash`/`slot`.
  - Go+/Go− → `page`; Store/Clear/Please → `store`/`clear`/`alt`; Pause/B → blackout.
- **Индикация:** `console_state` рисует: подсветка выбранных слотов (мигание), активная
  сцена, зажатый флеш, armed-Store (мигание кнопки Store), ALT-лампа, позиции фейдеров
  (master/sub/chan по режиму), тумблы сцен (мини-бары из снепшота, как сейчас).
- **Сцены играет СЕРВЕР** — панель только показывает `active_num`/`flash_held` и отправляет
  команды. Локальный `playScene/recordScene` с зашитыми CHS — удаляется.
- Хранение сцен-данных панелью (`scenes` dict, thumbs) — читается из `scene_store`/`console_state`.

## 8. Миграция и совместимость

- `scenes_store.json`: формат не меняем (`templates[name][idx] = {ch:val}`); старые
  сцены (только COB 200–207) валидны и в новом смысле (ненулевые каналы). Новые сцены —
  полные снепшоты. Требование «сцена = 256/512 полный снепшот» выполняется неявно (ноль = пусто).
- `routing_store.json`/`wing_input_map.json`: не трогаем физически; активный пресет
  роутинга в `console_mode=True` применяется ТОЛЬКО к энкодерам. Кнопки/фейдеры — консоль.
- `WingSender`: добавляется `CONSOLE_SOURCE`, `set_source_frame()`, `_depot_fader_levels`
  переписывается на консоль (позиции фейдеров из движка, а не из пресета роутинга).
- Старт сервера: движок чистый (мастера 0, сцена none, программер пуст, слоты пусты,
  mode normal, `_bypass=True` как сейчас) → «все каналы 0, аналог блекаута». Сцены из стора.
- Аварийный откат: `console_mode=False` возвращает старое поведение панели/крыла (роутинг).

## 9. Что НЕ входит в первый проход

- Мастер на флеш (флеш всегда 255 без мастеров — так и задумано).

## 11. Открытые вопросы (решены юзером 15.08)

1. **ALT = Please (70).** Подтверждено (в ряду Store/Clear; At — запасная).
2. **Флеш = замена на время нажатия**; отжата → возврат к прежней сцене. Субамастера
   фейдеров 3–8 = **наложение (HTP)** поверх NUM-сцены; точная механика «фейдер над
   флеш-кнопкой» уточняется на прогоне (задел: флеш = 100% своей сцены и перекрывает
   свой фейдер; сцена флеша заменяет всю картинку).
3. **Программер = прямые физические значения БЕЗ мастеров** (255 = физ. максимум).
   Мастера применяются только к слою сцен; в ALT супермастера заморожены и оператор
   сам правит диммер/строб-каналы.
4. **Энкодеры** — стопгап: прямой роутинг 41–44 (как сейчас).
5. **Клавиатура ПК остаётся:** Numpad0 = блекаут, цифры 1–9 = сцены 1–9 (обычный режим).
