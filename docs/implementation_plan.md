# План реализации: Двухрежимное голосовое управление DMX и Resolume

Этот план описывает технические шаги по внедрению голосового управления, разделенного на творческий режим репетиции (подготовка сцен через облачные модели) и быстрый реалтайм-режим живого выступления (управление локальной Qwen 3.6 MoE).

---

## 1. Точки интеграции и архитектура двух режимов

### Режим 1: Подготовка сцен (Оффлайн-режим)
* **API:** Python-сервер обращается к **OpenRouter** (Claude 3.5 Sonnet / GPT-4o).
* **Логика:** Модель генерирует сложную структуру нод, связей и фаз LFO (например, симметричные сдвиги фаз для 40 пикселей расчёсок).
* **Хранение:** Сгенерированная сцена сохраняется в локальную папку `projects/` как JSON-пресет с помощью существующего эндпоинта `/api/projects/save`.

### Режим 2: Живое шоу (Лайв-режим)
* **API:** Локальный запрос на `http://localhost:1234/v1` к локальной модели **Qwen 3.6 MoE** (через LM Studio).
* **Логика:** Модель не меняет структуру графа, а только:
  1. Вызывает загрузку сохраненных сцен из папки `projects/`.
  2. Быстро меняет параметры (яркость, цвет, скорость LFO) на уже существующих нодах.
* **Распознавание речи:** Полностью локальный **Whisper** (библиотека `faster-whisper` с GPU-ускорением CUDA).

## 3. Поэтапный план тестирования (Safe Sandbox)

1. **Изолированный тест Whisper (`scratch/whisper_test.py`):** Проверка скорости локального распознавания с CUDA на картах 4090/5080.
2. **Изолированный тест промптов (`scratch/ai_logic_test.py`):**
   * Проверка генерации сложных фазовых сдвигов для 40 пикселей панорамы расчёсок.
   * Проверка генерации простых лайв-команд переключения.
3. **Проверка API Resolume:** Тестовая отправка POST-запросов для запуска клипов в Arena.
4. **Интеграция в WebUI:** Перенос логики в основной интерфейс и тестирование сквозного прохождения команд.

## 4. Перспективы развития (Roadmap)

* **Автопилот по сценарию (Speech-to-Cue Auto Mode):** Разработка фонового сервиса сопоставления речи с текстовым сценарием (Word/JSON) для автоматического переключения сцен в Арене и DMX во время простых лагерных мероприятий.
* **Анализ сцены по камере (Qwen 3.6 VL):** Периодический анализ (1 кадр в 3–5 секунд) стандартной веб-камеры с помощью Vision-модели. Для захвата видеопотока используется **OBS Virtual Camera** или **obs-ndi**, чтобы не конфликтовать с трансляцией OBS в VK.
* **Сетевое управление звуком (Behringer X32 OSC):** Отправка OSC-сообщений по UDP для автоматического управления фейдерами громкости и мьютированием каналов микрофонов на цифровом пульте Behringer X32 в зависимости от активных сцен.
