# GrandMA2-onPC Wing — Reverse Engineering & Direct DMX

> Суть работ по проекту Lumina DMX (`N:\python_ide\DMX-ART-L`): реверс-инжиниринг
> китайского клона крыла grandMA2 onPC, прямая отдача DMX в USB без onPC,
> и маппинг физических органов управления крыла на DMX-каналы.
> Состояние: **полностью раскрыт ввод — 8 фейдеров + 4 энкодера + 28 кнопок
> работают без onPC. Ключ — ctl-пакет `04 90 04 01` (264 байта) каждый цикл.**

---

## 1. Цель

Крыло (VID `03EB`, PID `160B`, MA Lighting "onPC Wing", драйвер WinUSB) умеет
выводить DMX напрямую. Задача — гонять DMX из Lumina DMX **без** запущенного
grandMA2 onPC, а затем подцепить физические фейдеры/энкодеры/кнопки крыла к
DMX-приборам. **Выполнено.**

## 2. Железо и режимы

- VID/PID: `03EB` / `160B`. Два режима перечисления:
  - **boot mode** `bcdUSB = 0x200` — принимает загрузку прошивки.
  - **runtime mode** `bcdUSB = 0x100` — после прыжка прошивки; тут работает DMX и keepalive.
- Без keepalive/сессии крыло через ~3 с возвращается в boot mode.
- Интерфейс: EP_OUT `0x02`, EP_IN `0x81` (оба bulk, 512 байт).
- 2 выхода DMX, DMX-in, LTC, MIDI-in. Физически: 8 фейдеров, 4 энкодера, 28 кнопок.

## 3. Протокол (восстановлен по USBPcap-захвату onPC)

Все команды хост→крыло имеют вид `CMD 90 04 ...`, ответы крыла — `91 ...`.

- **Загрузка прошивки**: `01 90 04 00 00 00 00 00` + `02 90 ...` + сырые блоки по 512 Б.
  Захвачено в `tools/wing/wing_boot_seq.json` (71 пакет stage-0), прошивка —
  `tools/wing/wing_fw.bin` (34638 байт).
- **Init сессии**: `01 90 04 00 00 00 00 00` + `10 90 04 00 7c 00 00 00`.
- **CTL-пакет `04 90 04 01` (264 байта) — КЛЮЧЕВОЙ**. onPC шлёт его каждый цикл
  (~30 Гц, вперемешку с DMX и keepalive; тело — LED/fader-echo данные, сразу
  после init — нули). **Только пока хост шлёт CTL, крыло стримит полный вход
  (8 фейдеров + расширенные state-пакеты).** Без CTL — только 4 счётчика
  энкодеров. Реализовано как `wing_driver.CMD_CTL` + `Wing(full_session=True)`.
- **DMX-кадр**: `06 90 04 02 00 02 <universe:u16le> <512 байт DMX>`.
- **Keepalive**: `05 90 00 00` (посылается ~30 Гц, иначе сессия падает).
- **Shutdown**: `1a 91 00 00`.

Важный нюанс Windows/libusb: после пере-перечисления крыла нужен **свежий
контекст libusb** на каждый опрос (`open_wing` создаёт новый backend каждый раз),
иначе устройство не видно.

Полезное: захват `wing_boot_seq.json` содержит не только прошивку — **stage '1'
(1618 пакетов) это живая рантайм-сессия onPC**, из неё и был извлечён CTL-пакет.
Секция `runtime` хранит образцы `dmx_u1/dmx_u2/ctl_9004/init_9007/init_9010`.

## 4. Драйвер — `tools/wing/wing_driver.py`

- `Wing(full_session=True)` — класс с `start()/send_dmx()/stop()`, фоновым
  reader-потоком BULK IN и колбэком `set_input_callback(raw: bytes)`.
  В `full_session` шлёт `CMD_CTL` после init и каждый цикл в `send_dmx`.
- `send_dmx(u1, u2)` пишет universe 1 (и опц. 2) + CTL + keepalive.
- Тесты: `run_test()` (рампа/постоянные каналы), `run_comb_test()` — гоняет
  comb-прибор (адрес 250, 43 канала `comb_rgbw`).
  **Физически проверено — свет зажёгся без onPC.**
- Изолированный venv: `tools/wing/venv` (pyusb, libusb-package, aiohttp, pywin32).

## 5. Автозапуск на Windows

- Через **Планировщик задач** (задача `LuminaDMX`, AtLogon, Hidden, S4U, Highest),
  НЕ через pywin32-сервис (тот падает с `-1073741810`).
- `run_server_hidden.bat` ставит `LUMINA_SERVICE=1` (сервер не открывает браузер,
  пишет в `logs/lumina_service.log`).
- Скрипты: `install_autostart.ps1` / `install_autostart_admin.bat`,
  `uninstall_autostart.ps1`, `start_server_task.bat`, `stop_server_task.bat`.
- `server_v4.py`: `OUTPUT_MODE="wing"` с фолбэком на Art-Net; `WingSender`
  держит сессию (full_session=True) и авто-reconnect; `build_frontend()`
  пропускает сборку если есть `web/dist/index.html`.

## 6. Маппинг органов управления (РАСКРЫТ ПОЛНОСТЬЮ)

### 6.1 Инструменты
- **Пробник** — `tools/wing/wing_input_probe.py` + `probe_input.bat`: логирует
  все входные пакеты (держит keepalive, иначе крыло роняет сессию!).
- **Калибровщик** — `tools/wing/wing_calibrate.py` + `calibrate.bat`:
  интерактивно проводит по каждому органу (8 фейдеров → 4 энкодера → кнопки),
  показывает какие смещения пакета меняются, пишет `wing_calibrate_result.json`.
  Оба батника сами останавливают/поднимают задачу `LuminaDMX`.

### 6.2 Раскодированный формат (калибровка, полная сессия)

**State-пакет** — заголовок `03 90 7c 00 ...`, длина 140/144 (базовая), в
полной сессии бывают 200/392 и др. Счётчик — u16 @16.

**Фейдеры** — 8 × uint16 LE, **10-бит (0..1023)**, смещения @80..94.
ВНИМАНИЕ, внутренняя нумерация крыла `[3,4,5,6,7,8,1,2]`, поэтому в порядке
физических подписей:
```
фейдер 1 @92    фейдер 2 @94    фейдер 3 @80    фейдер 4 @82
фейдер 5 @84    фейдер 6 @86    фейдер 7 @88    фейдер 8 @90
```

**Энкодеры** — 4 × int32 **SIGNED** накопленные счётчики @32/36/40/44
(энкодеры 1–4 соответственно). Влево — уменьшается, вправо — увеличивается.
В DMX маппятся как **относительные приращения** виртуального 0..255
(`delta * sensitivity`). Историческая заметка: в раннем логе эти каналы были
ошибочно приписаны «фейдерам 1–4» — калибровка это опровергла.

**Button-событие** (трейлер к state-пакету любой длины):
```
<01|02> 91 08 00  <u32 counter>  <u32 value>
  01 = нажатие, 02 = отпускание
  value (low byte) = ID кнопки
```
Реальные кнопки: **42–45, 50–53, 57–61, 64–70 (без 65), 112–119, 126** —
всего 28. (ID 176–187 — артефакт одноразового init-dump, игнорируется.)

### 6.3 Маппер — `tools/wing/wing_input_mapper.py`
- `parse_faders(data)` → 8 × uint16 в физическом порядке 1..8.
- `parse_analog(data)` → 4 × int32 signed (энкодеры).
- `find_button_events(data)` → список `(id, pressed)`, магик `xx 91 08 00`.
- `WingInputMapper(write_dmx=None)`: фейдеры — абсолютное масштабирование
  `in_min/in_max` (по умолчанию 0..1023) → 0..255; энкодеры — накопление
  дельт в виртуальное значение с клампом; кнопки — momentary/toggle.

### 6.4 Карта — `tools/wing/wing_input_map.json`
- 8 фейдеров → DMX ch 1–8 (universe 1).
- 4 энкодера → DMX ch 41–44 (relative, sensitivity 1.0).
- 28 кнопок → DMX ch 11–38 (mode `momentary`).
- Подключено в `WingSender` (`server_v4.py:189-191`): `WingInputMapper(self.set_channel)`
  + `set_input_callback(mapper.on_raw_packet)`.

## 7. Решённая проблема: «крыло отдаёт только 4 канала»

В базовой сессии (прошивка + CMD_START/CMD_INIT2) крыло стримит только 4
счётчика энкодеров; фейдеры молчат **в любом виде** (полный дифф пакета и
init-dump это подтвердили). Решение найдено в захваченной рантайм-сессии onPC
(stage '1' в `wing_boot_seq.json`): onPC каждый цикл шлёт **CTL-пакет
`04 90 04 01` (264 байта)**. Реплей этого пакета (`full_session=True`)
полностью разблокировал ввод — калибровка подтвердила все 8 фейдеров.
